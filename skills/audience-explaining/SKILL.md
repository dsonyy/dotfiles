# Audience Explaining

Explain one thing several times, once for each reader below, ordered from least to most background:

1. **10-year-old**: an everyday analogy, no jargon.
2. **Non-technical, new to the domain**: what problem it solves and who uses it.
3. **Engineer, new to the domain**: map it onto familiar engineering ideas (data flow, inputs and outputs, what is automated).
4. **Non-technical, knows the domain**: domain terms and the business flow, no implementation details.
5. **Engineer, knows the domain**: domain terms plus how it works inside, with a pointer to the code.

## Rules

- Each explanation takes under a minute to read. Shorter is better.
- Each one stands alone. Add a detail only when that reader needs it.
- If the user names other readers, use theirs, keeping the least-to-most order.
- Ground it in the real system: read the code or docs first, never guess.
- Do not add a closing summary.
